## Trae「凭证已过期」误报（Swift 侧判据判错了对象）

现象：Trae 两个账号签到都成功，界面却把它们标成"过期/需重新登录"。

根因：**不是"前端自己定了几天过期"，是拿错了凭证判**。
`Models.credentialHint()` 读 `trae_auth.token`（JWT）里的 `exp` 跟当前时间比，过期即报红。
但 Trae 的 JWT 只有 8 小时（`exp = iat + 28800`），而签到链路
`TraeClient._post_authed` 是先用手头 JWT、撞 401/403/业务码 1001 就用长效会话
`X-Cloudide-Session` 调 `GetUserToken` 换一个全新 JWT 再重试 —— **存下来的 token 只是票根**。
实测：132trae 的 exp 已过 10 天、136 已过 15 小时，当天 09:00 签到照样 HTTP 200。

改法（`native/Sources/AutoCheck/Models.swift`）：
- `credentialHint()` Trae 分支只看 `session` 在不在；token 缺失也不算坏（签到时会现换）。
- `credentialSummary()` 不再显示"Token ******" / "Token 已过期"，改显示
  "长效会话 · 已保存 N 天"（新增 `savedDays(_:)`，读 `saved_at`；只作参考，不倒计时）。
- 删掉 `jwtExp(_:)` 与 `maskToken()`（死代码 + 防止有人再加回这个判据）。
- `AppModel.needsRelogin()`：`hint.color != .green` → `== .red`（中性色不该触发重登录入口）。

验证：`swiftc -typecheck` **0 error / 0 warning**；用真实账号结构编了 4 个 case 跑新判据
（exp 过 10 天 → 绿；过 1 天 → 绿；缺 session → 红；有 session 无 token → 绿），符合预期。

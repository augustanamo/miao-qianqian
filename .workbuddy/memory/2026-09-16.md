## 设置页交互重构（用户反馈："签到时间设置交互不太对，保存不了"）

### 根因（两条叠加，都指向"保存不了"）
1. **保存入口在页面最底部**。旧版是「草稿 + 底部 dirtyBar（有 N 项未保存 / 放弃修改 / 保存设置）」，
   dirtyBar 是 PageScroll 的最后一个元素 —— 设置页两列卡片本来就很长，它天然在首屏之外，用户改完签到时间根本看不到保存按钮。
2. **切页即丢草稿**。`ContentView` 用 `switch m.selectedPage` 渲染，切到账号管理再回来 SettingsView 被销毁重建，
   `@State times` 归零后 `onAppear` 从磁盘重读 —— 未保存的改动静默消失。
3. 放大问题的第三点：`DatePicker(.field)` 在 macOS 上要回车/失焦才把输入提交给 binding，点别处常拿到旧值。

### 定下的改法
- **设置页改为"即时生效"**：删掉 dirtyKeys/dirtyBar/commit/loadDraft 整套两段式状态，
  任何改动立刻 `m.pref.save()`；页头出现 1.6s 的"已保存"胶囊做反馈。
- **时间选择换掉 DatePicker**：改成「时 / 分」两个 `Menu` + `SelectBox`（点一下就写回，无提交时机问题）。
- **时间片交互重做**：编辑条从"左侧列"搬到"签到时间行正下方"，点哪个片就在下面调哪个；
  时间片用 `TimeSlot(Identifiable/UUID)` 取代 `ForEach(times.indices, id: \.self)`（增删后下标身份会串行错位）。
- **"下一个执行时间"不再用黑底**（旧版和"编辑中"同一种黑底，很容易误解），改为红圈描边 + `allowsHitTesting(false)`。
- **`AppModel.pref` 加 `@Published`**：旧版改设置后靠每秒 ticker 硬刷才更新。
- **launchd 重装防抖 0.5s**（`syncLaunchdIfNeeded()`）：连点 7 个星期圆点不该触发 7 次 launchctl unload/load。
  未开启自动签到时不安装任务（避免随手改个时间就把定时签到静默打开）。
- 顺手修：「执行日」全取消会写出永不触发的 plist → 拦掉最后一天 + `install()` 双层兜底；
  「至少一个时间点」→ 删到只剩一个时禁用删除（旧版静默重置成 21:30）；
  「恢复默认设置」加破坏性确认弹窗；「每日汇总提醒」文案从"21:30"（错的）改成实际触发的 +1 小时；
  「积分刷新频率」原本是个**假控件**（creditsRefreshMinutes 除了读写没有任何消费者）→ 接上前台定时刷新；
  「下次自动签到」计数改用 `AppModel.nextFire()`（真源 pref.times），不再读 plist 首个时间；
  launchd 倒计时按全部 StartCalendarInterval 逐条算最近一次（旧实现只取第一条 + 忽略星期）。

### 改动文件
`ViewSettings.swift`（整篇重写）、`AppModel.swift`、`Bridge.swift`（currentState/nextFireDate、install 兜底）、
`Views.swift`（状态栏文案 + 顶栏"下次"）、`ViewHelp.swift`（"改动即时生效"）。

## 13. 签到结果卡：异常改为弹窗详情 + 单账号重试（用户反馈）

用户原话："签到结果与异常，点击立即处理不应该去账号页面吧？是否应该先弹窗查看报错详情。然后点击重试是就当前行的账号重试吗？"

**答**：重试确实是行内单账号（`runSingleSign` → `checkin.py --only <name>`），但「立即处理」跳账号页是死胡同
—— 那一页只有重命名/删除，既看不到报错也没有重试按钮。

### 改动
- `Models.swift` 新增 `CheckinIssue`（state/name/hit）+ `diagnose()` 四分类：
  `.relogin`（凭证失效）/ `.retry`（偶发）/ `.wait`（网络超时）/ `.none`（平台受限）。
  关键词取自 checkin.py 实际文案（`登录态已失效`、`（HTTP 401）`、`CookieError` 等）。
- `AppModel`：删 `redBanners()`（返回拼好的 String），换 `issueItems() -> [CheckinIssue]`（fail + restricted 合并，按名排序）；
  `runSingleSign` 开头加「正在重试「X」」toast；结束 toast 改为**只报这一个账号**的结果（原报全局汇总，判断不出修好没修好）。
- `Views.swift`：`ResultCard` 重写为逐条可点行（账号名 + 报错摘要 + 详情），最多 4 条；日志折成底部链接。
  新增 `IssueDetailSheet`（520×470）：完整报错（可选中/复制）+ 发生时间 + 可能原因 + 账号信息
  + 重试（禁用于 `.none`）/ 复制 / 按平台的重新登录入口（WB 读本机态、Trae 重登、其余跳账号管理开面板）。
- `ViewHelp.swift` 常见问答案例同步为新流程。

### 两个实现细节（避免再踩）
- 弹窗 `@State` 存**账号名**而不是条目对象：重试成功后该账号从 issueItems 消失，存对象会失联。
- `LogHit` 的 `credits` 无默认值，构造占位要写全 `LogHit(time:date:msg:credits:)`。

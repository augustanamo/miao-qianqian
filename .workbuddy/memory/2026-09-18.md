# 2026-09-18

## 排查「定时签到改到 9 点却没执行」

### 症状
用户 9-16 把定时改成 09:00，9-18 过了点仍没有任何签到记录。

关键区分：launchd **确实按时触发了**，但命令跑不起来 —— "没触发"和"触发了但失败"是两回事，
唯一入口是 `logs/launchd.log` 与 `launchctl print`，不能只看 App 界面（界面当时还写着"已开启"）。

### 根因：plist 里那条 shell 命令串，两个坑叠加
`logs/launchd.log`（9-18 09:00 写入）只有四行，全是同一个错：
```
/bin/bash: /Users/augustanamo/Library/Application: No such file or directory
```
1. **路径含空格没加引号**。plist 里是
   `/bin/bash -l -c "cd <proj> && <python> <proj>/checkin.py >> log"`，
   而 `<python>` = `/Users/xxx/Library/Application Support/com.tencent.mac.marvis/.../python3`。
   bash 解析这行时把 `/Users/augustanamo/Library/Application` 当成命令名 → **退出码 127**。
2. **解释器路径写死且带版本号**。plist 里是 `…/MarvisAgent/Versions/1.0.0.10316/runtime/python311/bin/python3`。
   Marvis 在 **9-17 22:30 升级到 `1.0.0.10339`** 并删除了旧版本目录 →
   即便把引号补上，第二天照样失败。写进 plist 的那一刻它是存在的（`Py.detect()` 是动态扫描的），
   但 plist 是静态文件，环境一变就烂。

旁证：`launchctl print gui/501/com.marvis.autocheckin` → `runs = 2`、`last exit code = 127`。

### 修法：plist 只负责"什么时候跑"
新增 **`run_checkin.sh`**（项目根），每次执行时自己解析解释器：
`CHECKIN_PYTHON` → Marvis `Versions/*`（按 mtime 倒序取第一个可执行的）→ homebrew → `/usr/local` → `/usr/bin`；
错峰逻辑从命令行挪到 `CHECKIN_STAGGER` 环境变量；找不到解释器时打清晰报错并 exit 1。
- `Bridge.swift::install()`：ProgramArguments 改为 `[/bin/bash, <proj>/run_checkin.sh]`，
  **不再拼任何 shell 字符串**；安装前检查启动器存在；删掉 `escapedCmd`；错峰经 `EnvironmentVariables` 下发。
- `install_launchd.sh` 同步改为调启动器（原为 `/usr/bin/python3 checkin.py`）。

### 顺带修掉的第二处隐患：App 不会自愈
`syncLaunchdIfNeeded()` 里是 `guard launchd.installed else { return }`，
而 `installed` 只看 `launchctl list` 里有没有 label。服务掉线（plist 文件还在）时：
界面显示"未开启" → 用户以为自己没设过定时，App **也不会重装** → 签到无声停止。
改为 `installed = 服务在 launchctl 里 || plist 文件存在`，另加 `State.loaded` 单独记录是否真加载。
设置页改三态：**已开启 / 待生效（橙）/ 未开启**；倒计时在未加载时不显示（那个时间根本不会触发）。

### 关于加载：一个必须记住的环境限制
`launchctl bootstrap/load` **需要调用进程属于用户的 GUI 会话**。在自动化/后台环境里执行会得到
`Bootstrap failed: 5: Input/output error`，**与 plist 内容完全无关** —— 用最小 plist、放到 `/tmp` 再试
同样失败，而 `launchctl managername` 还显示 `Aqua`，很有迷惑性。别再往 plist 格式上找原因。

本机 plist 已改写为调用启动器（时间保持用户设的 09:00），但**服务此刻是未加载状态**。恢复方式：
- 用户在 App 设置页把「定时签到」关掉再打开（GUI 进程执行 load，最可靠）；
- 或用户在终端执行 `launchctl load ~/Library/LaunchAgents/com.marvis.autocheckin.plist`；
- 或重新登录（launchd 在登录时扫描 LaunchAgents）。
- 注意：**旧版 App 的判断是 `installed=false`，不会自动重装**，必须重新 build 后再打开。

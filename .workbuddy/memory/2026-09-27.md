# 2026-09-27

## 菜单栏图标换成应用图标（黑猫）+ 不再占程序坞

需求：关掉窗口后驻留在顶部的那枚图标换成应用图标（原来是 SF Symbol
`checkmark.seal.fill`）；同时**程序坞不要再出现第二个图标**（此前顶部和程序坞两处都有）。

做法：
1. **新建 `make_menubar_icon.py`**：从 `assets/AppIcon.icns`（白底 + 黑猫 1024²）生成
   菜单栏专用图标 `assets/menubar/MenuBarIcon.png`(18×18) / `MenuBarIcon@2x.png`(36×36)。
   关键手法：**拿亮度当 alpha** —— 猫身黑（不透明）、白底与眼白（透明，于是眼睛成了挖空的洞）、
   毛边灰阶平滑过渡保住抗锯齿。产出的 1x/2x 两张 size 都是 18pt。
2. **`AutoCheckApp.swift`**：
   - `menuBarIcon()` 三层兜底：`MenuBarIcon`（isTemplate，随菜单栏明暗自动反色）→ 完整 `AppIcon`
     → SF Symbol（裸跑二进制没有 bundle 资源时）。
   - `NSApp.setActivationPolicy(.regular)` → `.accessory`。
3. **`make_native_app.sh`**：Info.plist 加 `LSUIElement=true`（**启动即**不占程序坞，避免
   "先冒出来闪一下"）；新增复制 `assets/menubar/MenuBarIcon*.png` 到 Resources 的步骤
   （没有就现跑脚本生成，需要 PIL）。

为什么不能直接把整张 App 图标贴上去：白底圆角卡片在菜单栏里像贴了张小纸片；更关键的是
template 渲染只认 alpha，白底与眼白都会被涂成前景色 → 黑猫会变成一块实心色块且没有眼睛。

实测（`swiftc` 小程序加载 PNG）：18×18px / 36×36px 两张，point 尺寸均为 18×18；
alpha 分布 不透明 29~33% / 抗锯齿过渡 11~18% / 透明 51~54%（证明白底与眼睛确实挖空）。
`swiftc -typecheck` 0 error / 0 warning；`bash -n make_native_app.sh` 通过。未 build。

### 踩到的坑
- **PIL 把预览图存成 "L" 模式 = 白看**：读回来 convert("RGBA") 后 alpha 全是 255
  （"覆盖率 100%"），差点据此以为抠图失败。预览必须同样存 RGBA。
- PIL 加载 `/System/Library/Fonts/PingFang.ttc` 画中文标注会渲染成方块 →
  示意图文字改用 Helvetica。
- 自查图与交付预览存 `.workbuddy/preview/menubar-icon-check.png`（已 gitignore）。

### 行为变化（需要用户知道）
- 应用不再出现在程序坞与 Cmd+Tab；**回到窗口的唯一入口是顶部那只猫**（点开 →「显示主窗口」）。
- Finder 里双击 .app 仍能唤回窗口（`applicationShouldHandleReopen` 保留）。

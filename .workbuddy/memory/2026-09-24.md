## 用户报的两件事：「重新登录」按钮全变灰 / WorkBuddy 读本机 token 失败

### ① 「点击的时候所有的一起被点了」——是我们自己状态用错了

`ViewAccounts.reloginChip` 的文案与配色读的是**全局** `m.loginRunning`：

```swift
Text(m.loginRunning ? "登录中…" : "重新登录")     // ← 点一个账号，所有账号都变"登录中…"
```

`loginRunning` 的语义是"有没有登录正在进行（一次只允许一个）"，不是"这个账号在登录"。
`AppModel` 里本来就有**逐账号**状态 `@Published var loginAccount` —— 注释就写着"用于逐账号
显示『登录中…』"，视图写的时候漏用了。

**改**：文案与配色改用 `m.loginAccount == acc.name`；`.disabled(m.loginRunning)` 保留
（并发登录不该发生）。所以现在只有被点的那个账号显示"登录中…"，其余保持"重新登录"（禁用态）。

### ② WorkBuddy 读本机 token 失败——**对方把凭据加密了，无解**

`workbuddy.py --probe` 报 `has_token: false`，理由原本写的是"请重新登录 WorkBuddy 桌面端" ——
**这句是误导**：重登桌面端之后凭据照样是加密的，症状一模一样。

真实情况（已挖到实现层）：
- `workbuddy-desktop.info` 里 `auth.accessToken` / `refreshToken`、`account.nickname` / `phoneNumber`
  全变成 `{"$wbEncrypted": 1, "envelope": "<base64>"}`（昵称也是加密的，别再当字符串用）；
- 实现在 `app.asar/main/credential-protection.js` 的 `ProtectedFieldCodec`，
  真正的加解密在原生模块 `app.asar.unpacked/native/turing-sdk/build/Release/turing_sdk.node`
  （腾讯 TuringShield），**密钥不落盘** → 第三方拿不到明文。
- 定位手法：解析 asar 头部（`json.JSONDecoder().raw_decode`，注意 JSON 从偏移 **16** 开始、
  数据区 base = `8 + header_size`），把 `wbEncrypted` 的字节偏移映射回文件名。
  这条链子写进了 skill `electron-private-api-mining` 的踩坑区。

**改**（Python）：
- `read_auth()` 新增 `encrypted` 字段 + `is_encrypted_field()` / `plain_str()` 两个小工具；
  reason 改成如实说明"桌面端把凭据改成加密存储…请改用扫码登录"。**顺手堵了一个泄漏**：
  原来 `nickname` 会把整个加密信封当字符串放进 probe 输出。
- `checkin_all_json()` 的"本机登录态来源"失败分支不再写死一句"请先扫码登录"，
  改为带上真实原因 `exc`（否则日志里看不到"加密"二字，UI 诊断也就匹配不到正确的分支）。
- 模块 docstring 里"v5.3.8+ 明文写入"的说明已过时，改掉了。

**改**（Swift）：
- `AppModel` 新增 `wbEncrypted` / `wbReason`（原因原文由 Python 给，UI 不再自己编一句）；
  探针解析 `encrypted` 字段。
- WorkBuddy 面板：加密时**不再摆一个永远按不动的「读取本机登录态并添加」按钮**
  （等于骗用户反复点），改成一句话指向「扫码登录」；状态色用橙（受限）而不是红（失败）——
  账号是好的，只是我们读不到。
- `CheckinIssue.diagnose()` 新增分支（**必须排在通用"登录态失效"之前**）：
  命中「读不到明文 / 加密存储 / $wbencrypted」→ 标题「本机登录态已读不到」+ 出路指向扫码。
  跑了分类表实测：加密→relogin、文件缺失→relogin、smzdm 401→relogin、超时→wait、
  平台受限→none，**无误报**。

### ③ 顺带修掉一个连带漏洞：WorkBuddy 账号的**两种来源**被当成了一种

`accounts.json` 里同时有：
- `workbuddy-悱` → `source` 缺省（=「本机登录态」来源），**没有** token，签到实时读桌面端 → **现在签不了了**；
- `workbuddy-WAV` → `source: "oauth"`，自带 access_token/refresh_token → **与桌面端无关**。

而旧代码有两处按"WorkBuddy 全看桌面端"处理，加密后会变成**永久假警报**：
- `healthCard`：`if acc.isWorkBuddy { return m.wbHealthy == false }` → WAV 无辜被报"凭据失效"。
- `relogin()`：WorkBuddy 一律走 `runWorkBuddyRefresh`（重读桌面端）→ 对 WAV 是完全错误的动作，
  对已加密的悱也注定失败。

**改**：
- `needsRelogin()` 里收口：`acc.isWorkBuddy && acc.workbuddy_auth?.source != "oauth"` 时
  直接返回 `wbHealthy == false`（**静态事实，不必等今天签到失败**——否则健康卡说"点下方重新登录"
  而账号行没有按钮，就是 smzdm 那个漏洞的同一形状）；oauth 账号走通用判断。
- `healthCard` 一律走 `needsRelogin`，删掉 WorkBuddy 的特殊分支（口径统一）。
- 新增 `AppModel.workbuddyReloginUsesOAuth(_:)` 作为**唯一判据**，
  `relogin()` 的路由和 `Views.reloginLabel` 的文案都调它 → 不会再出现"按钮写『读取本机登录态』、
  点下去弹扫码页"。
- `reloginChip` 的 tooltip 原本写 `acc.credentialNoun`（WorkBuddy/Trae 会得到"Cookie"这种错话），
  改为按平台给"登录态 / 登录令牌"。

## ④「重新登录后账号状态不更新」= 换了凭据 ≠ 改了状态

**现象（用户报）**：重新登录成功后账号行状态没更新（还是红的"签到失败"、仍挂「重新登录」），
但手动签到能成功。

**根因**：账号行的状态胶囊、凭证健康卡、「重新登录」入口，**全部从今天的签到日志推出来**
（`ParsedLogs.status`，同日优先级 成功 > 受限 > 失败）。而**换凭据这个动作不写日志** ——
所有登录完成分支原来只调 `loadAccounts()`，那刷的是**凭据快照**，不是状态。
于是界面继续复述上午那条 FAIL，看起来就像"重新登录根本没生效"。
日志实证：`11:07:34 FAIL`（本机登录态读不到）→ `11:08:01` OAuth 扫码写盘（source 翻成 oauth）
→ `11:08:22 OK`；UI 在 11:08:01~11:08:22 之间仍显示失败。

**改法**：`AppModel.verifyAfterRelogin(_:)` —— 换完凭据**真签一次自证**，成功会在今天留下
新记录，状态按优先级自然翻正。四条分支**都会给出反馈**（扫码成功却一声不吭，
用户照样以为没成功）：
- 已启用且今天未签 → `runSingleSign(name, purpose: .verifyAfterLogin)`；
- 今天已签 → 只为"刷新一下"再打一次对方接口不值当，提示"（今天已签到）"收工；
- 未启用 / 已停用 / 查不到 → 提示"登录态已更新"收工；
- 有签到正在进行 → 提示一声，等它自己 `parseLogs`（不会漏）。

**调用面**：`relogin()` 传 `relogin: true`；`runTraeLogin` / `runWorkBuddyOAuth` 各加一个
`relogin` 参数（默认 false = 新增路径，行为不变）；cookie 平台复用既有的 `mode == "relogin"`；
`runWorkBuddyRefresh` 成功后同样自证。另：`runWorkBuddyOAuth` 成功后补 `probeWorkBuddy()`
—— 探针结果是"本机登录态"来源账号还给不给入口的判据，不刷新就是拿旧结论去判。

`runSingleSign` 新增 `purpose`（`.retry` / `.verifyAfterLogin`），**只影响文案**：
换完凭据自动验证却照抄"正在重试…"，用户会以为自己点错了什么。

**验证**：`swiftc -typecheck`（`-plugin-path MacOSX.platform`）**0 error / 0 warning**；
未跑真实签到（会真打对方接口），未 build。
